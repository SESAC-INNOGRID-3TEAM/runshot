## 1. 프로젝트 개요
---
### 한 줄 정의
RunShot 배번호 사진 검색 서비스

### 제품 목표
마라톤·러닝 행사에서 촬영된 대량 사진을 배번호(Bib Number) 자동 인식으로 인덱싱하여 참가자가 배번호 입력만으로 3초 내 본인 사진을 검색·다운로드할 수 있게 한다.

### 배경
현재 대회 사진은 구글 드라이브/SNS/오픈채팅 등으로 수천 장이 일괄 공유되어 참가자가 직접 찾아야 하고, 무차별 배포로 개인정보·초상권 노출과 원본 다운로드 불편이 발생한다. 배번호 기반 분류 시스템이 없어 본인 사진 식별이 어렵다. 로컬 전용(인터넷 미연결) 환경에서 3인 3일 MVP로 구현한다.

### 사용자 문제
참가자는 수천~수만 장의 사진에서 본인 사진을 찾기 위해 많은 시간을 들이거나 결국 찾지 못한다. 주최측/촬영자는 대량 사진 배포·관리 부담이 크고, 개인정보·초상권 리스크를 통제하기 어렵다.

### 해결 방안
촬영자가 이벤트별로 사진을 대량 업로드하면 비동기 OCR 파이프라인이 배번호를 자동 인식해 태그로 저장한다. 참가자는 이벤트 선택 후 배번호를 입력해 해당 사진만 갤러리로 확인하고 개별/ZIP 다운로드한다. 인식 실패 사진은 Organizer/Photographer가 수동 태깅으로 보정한다.

### 차별점
배번호 단일 키 기반의 즉시 검색(프라이버시 by design)과 업로드→큐→워커 OCR의 비동기 파이프라인을 MVP에 내장한다. Presigned URL로 서버를 경유하지 않고 로컬 MinIO에 직접 업로드/다운로드하여 대량 처리에 최적화한다.

### 타겟 사용자
1) 참가자(Participant): 30~50대 마라톤/러닝 동호인, SNS 공유 선호, 배번호로 빠르게 ‘내 사진’만 찾고 다운로드/공유하고 싶음. 2) 촬영자(Photographer): 대회 공식 사진작가/자원봉사자, 수천 장을 한 번에 올리고 배포 문의를 줄이고 싶음. 3) 주최측(Organizer): 대회 운영 담당자/러닝 클럽 매니저, 이벤트별 사진을 체계적으로 관리하고 참가자 경험을 개선하고 싶음. 4) Admin: 운영/관리자, 사용자 역할 및 OCR 실패 현황을 관리.

### 사용자 시나리오
- 촬영자: 이벤트 선택 → 사진 200장 단위로 업로드 → 진행률 확인 → 업로드 완료 알림으로 OCR 큐 발행 → 처리 현황 확인.
- 참가자: 이벤트 목록에서 이벤트 선택 → 배번호 입력 → 썸네일 갤러리에서 사진 확인 → 라이트박스 미리보기 → 개별 또는 ZIP 다운로드.
- Organizer/Admin: 이벤트 생성/수정 → OCR 인식 실패 목록 확인 → 수동 배번 태깅으로 보정 → 재검색 가능 상태로 전환.
- Admin: 사용자 목록 조회 → 역할 변경 → 이벤트 삭제 시 데이터 정리(cascade).

### 핵심 지표
- 배번호 검색 응답 시간: 500ms 이하(캐시 HIT 시 50ms 이하)
- OCR 처리 시간: 장당 5초 이하
- 업로드 성공률 및 재시도 성공률
- 인식 성공률(= done/(done+unrecognized)) 및 수동 보정 비율
- 검색 후 다운로드 전환율(개별/ZIP)

### 리스크
- Tesseract OCR 정확도 한계(70~85%)로 인식 실패가 다수 발생 가능 → 수동 태깅/재처리 플로우 필요
- 로컬 전용 환경 제약(인터넷 미연결)으로 라이브러리/모델 배포 및 업데이트 어려움
- 대량 파일 업로드 시 브라우저/네트워크 병목 및 저장소 용량 이슈
- 개인정보/초상권 이슈: 접근 제어·Presigned URL 만료 관리 미흡 시 유출 가능
- 3인 3일 MVP 일정 리스크: 범위 통제 실패 시 완성도 저하

### 카테고리
> 소셜 / 커뮤니티

### 사용자 역할
> Participant, Photographer, Organizer, Admin

### 디바이스 (기기)

## 1. 사용자 인증 및 권한 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

이메일/비밀번호 기반 회원가입·로그인과 JWT 세션(Access/Refresh) 및 역할 기반 접근 제어를 제공한다. 관리자는 사용자 역할 변경이 가능하다.

**수용 기준:**
```
1. ○ 이메일 형식 검증 후 회원가입이 가능하다.
2. ○ 비밀번호는 8자 이상이며 영문+숫자 조합을 만족해야 한다.
3. ○ 로그인 성공 시 Access Token(1시간)과 Refresh Token(7일)을 발급한다.
4. ○ Refresh Token으로 만료된 Access Token을 재발급할 수 있다.
5. ○ 로그아웃 시 Refresh Token이 무효화된다.
6. ○ 기본 역할은 Participant이며, Admin이 사용자 역할을 변경할 수 있다.
```


### 1.1 이메일 회원가입/로그인 및 토큰 발급
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Participant, Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

이메일/비밀번호로 회원가입 및 로그인을 제공하고, 로그인 성공 시 JWT Access/Refresh 토큰을 발급한다.


#### 1.1.1 회원가입 입력 검증 및 기본 역할 부여

회원가입 시 이메일 형식과 비밀번호 정책(8자 이상, 영문+숫자)을 검증하고, 신규 사용자의 기본 역할을 Participant로 저장한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 1.1.2 로그인 및 JWT 발급 정책

로그인 성공 시 Access Token(1시간)과 Refresh Token(7일)을 발급하고, 이후 private API 호출 시 Authorization 헤더로 Access Token을 검증한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 1.2 토큰 갱신 및 로그아웃
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Participant, Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

Refresh Token으로 Access Token을 재발급하고, 로그아웃 시 Refresh Token을 무효화한다.


#### 1.2.1 토큰 갱신 API

만료된 Access Token에 대해 Refresh Token을 검증하여 새 Access Token을 재발급한다. Refresh Token 만료/폐기 시 갱신을 거부한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 1.2.2 로그아웃 및 Refresh Token 무효화

로그아웃 시 서버 저장소(예: Redis)에서 Refresh Token을 폐기하여 재사용을 방지한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 1.3 역할 기반 접근 제어 및 역할 변경(관리자)
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)

API/화면 접근을 역할(role)로 제어하며, Admin이 사용자 역할을 변경할 수 있다.


#### 1.3.1 역할 기반 API 접근 제어

participant/photographer/organizer/admin 역할에 따라 이벤트 생성, 업로드, 관리 API 접근을 제한한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 1.3.2 관리자 사용자 역할 변경

Admin이 사용자 목록을 조회하고 특정 사용자의 역할을 변경할 수 있다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)

## 2. 이벤트 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

이벤트(대회/행사)를 생성·조회·수정·삭제하고, 이벤트 상세에서 업로드/인식 상태 요약 정보를 제공한다.

**수용 기준:**
```
1. ○ Organizer 이상만 이벤트를 생성/수정할 수 있다.
2. ○ 이벤트 목록은 최신순 정렬이며 페이지당 20개로 조회된다.
3. ○ 이벤트 상세에서 총 사진 수, 인식 완료 수, 인식 실패 수가 표시된다.
4. ○ Admin은 이벤트를 삭제할 수 있으며, 삭제 시 연결된 사진/태그 데이터가 cascade 삭제된다.
5. ○ 이벤트 커버 이미지 업로드를 지원한다(선택).
```


### 2.1 이벤트 생성/수정(Organizer+)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

Organizer 이상이 이벤트 이름/날짜/장소/설명/커버 이미지를 입력해 이벤트를 생성·수정한다.


#### 2.1.1 이벤트 생성 폼/API 필드

이벤트 생성 시 이름, 날짜, 장소, 설명, 커버 이미지 키를 저장하고 organizer_id를 생성자 사용자로 기록한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 2.1.2 이벤트 수정 정책

Organizer 이상이 이벤트 필드를 수정할 수 있으며, 권한 없는 사용자는 거부된다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 2.2 이벤트 목록 조회(페이지네이션)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Participant, Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

이벤트 목록을 최신순으로 페이지당 20개 조회한다.


#### 2.2.1 이벤트 목록 페이지네이션/정렬

이벤트 목록은 최신순 정렬이며 페이지당 20개로 응답한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 2.3 이벤트 상세 및 상태 요약
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Participant, Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

이벤트 상세에서 총 사진 수/인식 완료 수/인식 실패 수 등 업로드·인식 상태를 요약해 보여준다.


#### 2.3.1 이벤트 상세 상태 요약 계산

이벤트 상세에서 photos의 ocr_status를 집계하여 총 사진 수/인식 완료(done)/인식 실패(unrecognized)를 제공한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 2.4 이벤트 삭제(Admin)
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)

Admin이 이벤트를 삭제하면 연결된 사진/태그 데이터가 cascade 삭제된다.


#### 2.4.1 이벤트 삭제 및 데이터 정리

Admin이 이벤트 삭제 시 해당 이벤트의 photos 및 photo_bib_tags가 함께 삭제되도록 cascade 규칙을 적용한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)

## 3. 사진 대량 업로드 및 저장
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

촬영자/주최측이 브라우저에서 다중 사진을 대량 업로드하고, Presigned URL로 로컬 MinIO에 직접 저장하며 업로드 진행률과 재시도를 지원한다.

**수용 기준:**
```
1. ○ 회당 최대 200장, 각 파일 20MB 이하로 업로드할 수 있다.
2. ○ Presigned URL 방식으로 앱 서버를 경유하지 않고 MinIO에 직접 업로드된다.
3. ○ 동시 업로드는 최대 5개이며 나머지는 큐잉된다.
4. ○ 파일별 진행률(Progress Bar)이 표시된다.
5. ○ 업로드 실패 파일 목록과 재시도 버튼이 제공된다(선택).
6. ○ 동일 이벤트 내 파일명+파일크기 기반 중복 업로드를 방지한다(선택).
```


### 3.1 Presigned URL 기반 다중 파일 업로드
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

브라우저에서 다중 파일을 선택해 Presigned PUT URL로 MinIO에 직접 업로드한다(회당 최대 200장/각 20MB).


#### 3.1.1 Presigned PUT URL 발급

업로드 요청 시 파일명/크기/콘텐츠 타입을 받아 MinIO Presigned PUT URL을 발급한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 3.1.2 업로드 포맷/용량/개수 제한

JPEG/PNG/WEBP만 허용하며, 파일당 20MB 이하 및 회당 최대 200장 제한을 적용한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)

## 4. 배번호 자동 인식 파이프라인(비동기 OCR)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

업로드 완료 이벤트를 큐로 전달하고 워커가 이미지 전처리 후 OCR로 배번호를 추출·저장한다. 실패는 unrecognized로 관리하며 재시도/DLQ를 지원한다.

**수용 기준:**
```
1. ○ 업로드 완료 시 RabbitMQ 큐에 메시지가 발행된다.
2. ○ 워커가 메시지를 소비해 전처리(회색조/대비 강화 등) 후 OCR을 수행한다.
3. ○ 2~5자리 숫자 후보를 추출하고 confidence가 가장 높은 값을 대표 배번호로 저장한다.
4. ○ 복수 배번호가 인식되면 모두 태그로 저장할 수 있다(선택).
5. ○ 인식 실패는 ocr_status=unrecognized로 저장되며 검색에서 제외된다.
6. ○ 워커 실패 시 최대 3회 재시도 후 DLQ로 이동한다(선택).
```


### 4.1 업로드 완료 알림 및 RabbitMQ 메시지 발행
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

업로드 완료된 사진에 대해 서버가 메타데이터를 저장하고 RabbitMQ 큐에 OCR 작업 메시지를 발행한다.


#### 4.1.1 업로드 완료 처리 및 사진 메타데이터 저장

클라이언트가 업로드 완료를 알리면 photos 레코드(storage_key, original_filename, file_size, shot_at, ocr_status=pending)를 생성/갱신한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 4.1.2 RabbitMQ OCR 작업 메시지 발행

업로드 완료된 photo에 대해 event_id와 photo_id/storage_key를 포함한 메시지를 RabbitMQ에 발행한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 4.2 OCR 워커 처리(전처리+Tesseract)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)

워커가 메시지를 소비해 이미지 전처리 후 Tesseract OCR로 숫자를 추출하고 상태(done/unrecognized)를 저장한다.


#### 4.2.1 워커 OCR 처리 상태 전이

워커는 처리 시작 시 ocr_status=processing으로 변경하고, 완료 시 done 또는 unrecognized로 저장한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 4.2.2 이미지 전처리 및 Tesseract OCR 실행

Pillow로 회색조 변환/대비 강화 등 전처리 후 pytesseract로 OCR을 수행한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 4.3 배번 후보 추출/저장 및 재시도/DLQ(선택)
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)

2~5자리 배번 후보를 추출해 confidence 기반 대표값 및 복수 태그를 저장하고, 실패 시 최대 3회 재시도 후 DLQ로 이동한다.


#### 4.3.1 배번 후보 추출 규칙

OCR 결과에서 2~5자리 숫자 문자열을 후보로 추출한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 4.3.2 confidence 기반 대표 배번 및 복수 태그 저장

confidence가 가장 높은 후보를 대표로 취급하되, 복수 후보를 photo_bib_tags에 저장할 수 있다(선택).
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 4.3.3 재시도 및 DLQ 정책(선택)

워커 처리 실패 시 최대 3회 재시도 후 DLQ로 이동시킨다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)

## 5. 배번호 검색 및 사진 갤러리/다운로드
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중

참가자가 이벤트+배번호로 사진을 검색하고 갤러리/라이트박스에서 확인 후 개별 또는 ZIP으로 다운로드할 수 있다.

**수용 기준:**
```
1. ○ 이벤트+배번호 조합으로 사진을 검색할 수 있다.
2. ○ 검색 결과는 촬영 시각 오름차순으로 정렬된다.
3. ○ 썸네일 그리드(3열, 반응형)로 표시된다.
4. ○ 라이트박스에서 이전/다음 탐색과 개별 다운로드가 가능하다.
5. ○ 전체 ZIP 다운로드를 요청하면 백그라운드 생성 후 다운로드 링크가 제공된다(선택).
6. ○ 검색 결과가 없으면 안내 메시지와 수동 신고 링크가 표시된다(선택).
```


### 5.1 이벤트+배번 검색 API
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Participant, Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

이벤트 ID와 배번을 입력받아 해당 태그가 붙은 사진을 조회한다(인식 실패 사진 제외).


#### 5.1.1 검색 쿼리 조건 및 정렬

event_id와 bib_number로 photo_bib_tags를 조회하여 photos를 반환하며, shot_at 오름차순으로 정렬한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 5.2 검색 결과 갤러리 및 라이트박스
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Participant, Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)

검색 결과를 썸네일 그리드로 표시하고, 라이트박스에서 이전/다음 탐색 및 개별 다운로드를 제공한다.


#### 5.2.1 검색 결과 썸네일 그리드

검색 결과를 3열 반응형 썸네일 그리드로 표시한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Participant, Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)


#### 5.2.2 라이트박스 미리보기 및 개별 다운로드

사진 클릭 시 라이트박스에서 이전/다음 탐색을 제공하고, Presigned GET URL(유효 1시간)로 개별 다운로드한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 작성중 | **역할**: Participant, Photographer, Organizer, Admin | **기기**: 웹(데스크톱/모바일 브라우저)


### 5.3 전체 ZIP 다운로드(선택)
